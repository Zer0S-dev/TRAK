TRAK 3.0.6 - CHANGELOG

Date: 2026-08-28

NETWORK ARCHITECTURE
- Reworked the network state machine from scratch around one simple priority loop:
  Wi-Fi -> 4G -> Wi-Fi -> 4G -> ...
- Only one transport state is managed at a time.
- Wi-Fi has priority whenever the machine enters/re-enters the network sequence.
- While Wi-Fi is active, no 4G search is performed.
- While 4G is active, no Wi-Fi scan is performed.
- When the active transport is lost, the state changes to the other transport.
- If neither transport is available, the tracker remains OFFLINE and retries the
  sequence with Wi-Fi first.

CORE ASSIGNMENT
- Core 1 now owns the complete NetworkManager state machine.
- NetworkManager task is pinned to Core 1.
- CommunicationTask remains on Core 0 for modem/GNSS/Trackserver communication.
- Network decisions are no longer made by CommunicationTask.

INTERNET VALIDATION
- Removed the separate Wi-Fi Internet check from network selection.
- Removed the separate cellular DNS Internet check from network selection.
- A real Trackserver transmission is now used to validate end-to-end connectivity.
- One failed Trackserver transmission does not immediately switch networks.
- Three consecutive failed Trackserver transmissions trigger a transport change.
- A successful Trackserver transmission resets the failure counter.
- A physical Wi-Fi disconnection causes an immediate Wi-Fi -> 4G transition.
- Cellular registration is checked periodically; a lost registration causes an
  immediate 4G -> Wi-Fi transition.
- Cellular registration checks are throttled to avoid repeatedly querying the
  A7670 every loop.

COMMUNICATION / NETWORK SEPARATION
- CommunicationTask reports the result of real Trackserver transmissions to
  NetworkManager.
- Only NetworkManager changes ActiveNetwork.
- Buffer transmission failures are also reported to NetworkManager.
- No direct network switching remains in CommunicationManager.

WIFI
- A configured Wi-Fi connection is considered established when the STA is actually
  connected.
- Internet is not tested with a separate socket before declaring Wi-Fi active.
- The next real Trackserver transmission determines whether end-to-end Internet
  access works.
- Active Wi-Fi credentials are checked so a Dashboard modification of the active
  profile forces a clean reconnection.

4G
- PDP activation establishes the cellular transport.
- Internet is not tested with a separate AT+CDNSGIP check before declaring 4G active.
- The next real Trackserver transmission validates end-to-end Internet access.
- AT+CEREG? is used only as a periodic physical registration check.

CLEANUP
- Removed obsolete network health/retry decision code from CommunicationManager.
- Removed obsolete autonomous Wi-Fi scanning logic that could operate while 4G was
  active.
- Removed obsolete checkWiFiInternet()/checkCellularInternet() network-selection
  paths.
- Removed obsolete networkLastAttempt/networkSetLastAttempt dependency.
- Updated firmware version to 3.0.6.
- Updated dashboard-reported firmware version to 3.0.6.
- No new Markdown documentation was added.

IMPORTANT
- LED behavior has NOT been redesigned in this version.
- The purpose of 3.0.6 is to stabilize and simplify the Wi-Fi/4G state machine first.
- LED rules will be handled separately after network behavior is validated.
